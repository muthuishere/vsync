# `vsync` v0.15.0 — Runtime library redesign

**Status:** design · target packages `vsync-s3-client` (Python ref impl), `@muthuishere/vsync-s3-client` (TS), `github.com/muthuishere/vsync/libraries/go` (Go), `io.github.muthuishere:vsync-s3-client` (Java) · breaking — drops env-var reading, drops fallback chain, renames everything to one Firebase-style factory.

One theme: **the runtime library is a pure decryption client.** It takes two opaque strings (the bootstrap blob and the passphrase), does one S3 round trip, and exposes the decrypted vault through a tight 7-method surface. It does **not** read environment variables, **does not** fall back to `os.environ` when a vault key is missing, and **does not** ship convenience helpers that obscure where bootstrap inputs come from. The operator's app holds the bootstrap; the lib decrypts what the operator passes in.

For prior context, see [`v0.2-secret-lib.md`](./v0.2-secret-lib.md) (RQE1 envelope), [`v0.4-audit-log.md`](./v0.4-audit-log.md) (RQEM0001 manifest seal + generation counter), [`v0.10-runtime-token-cli.md`](./v0.10-runtime-token-cli.md) (the CLI side that produces `VSYNC_CONFIG`), [`v0.11-conformance-test-vectors.md`](./v0.11-conformance-test-vectors.md) (cross-language conformance corpus — v0.15 regenerates it), and [`v0.12-vsync-s3-client.md`](./v0.12-vsync-s3-client.md) (the API this spec supersedes).

Decisions locked from the design huddle (referenced where applied):

- **Q1** — Factory name is `open` across every language. No `create`, no `initialize`, no `from_env`. One name.
- **Q2** — No `close()` method. The client holds no OS-level resources; explicit `close` would be ceremony.
- **Q3** — No env-var helpers anywhere in the library. No `open_with_env()`, no separate `vsync_s3_client.env` module, no `from_environment()` factory. Operators write `VsyncClient.open(os.environ["VSYNC_CONFIG"], os.environ["VSYNC_PASSPHRASE"])` themselves. Three lines. The lib's responsibility ends at "decrypt what I'm handed."
- **Q4** — `env(key)` is **vault-only**. Returns `None` if the key is absent in the vault. No `os.environ` fallback, no `defaults={}` parameter, no per-key override.
- **OptionB (safe-restart)** — `status(test_passphrase=...)` does a trial decrypt of the *latest* remote bundle and sets `safe_to_restart` on the returned Status. Lets the operator verify that an updated `VSYNC_PASSPHRASE` works before triggering a process restart.
- **I** — pre-1.0; no compat shims; fail-loud on unknowns (inherited from v0.13).

## 1. Diff from v0.12

| Aspect | v0.12 (shipped) | v0.15 (this spec) |
|---|---|---|
| Open paths | `open()` reads `VSYNC_CONFIG` + `VSYNC_PASSPHRASE` from env; `open_with(config=, passphrase=)` takes strings | **Single factory:** `VsyncClient.open(config_blob, passphrase)`. Both positional. No env reads anywhere. |
| `_FILE` convention | `VSYNC_CONFIG_FILE` / `VSYNC_PASSPHRASE_FILE` resolved inside the lib | **Dropped from the lib.** Operators that want file-backed bootstrap read the file themselves: `VsyncClient.open(open("/run/secrets/vsync-config").read().strip(), …)` |
| Get env var | `get_env(key)` with fallback `vault → os.environ → defaults → None` | `env(key)` returns vault-only or `None`. No fallback. |
| Has env var | `has_env(key)` | **Dropped.** Replace with `v.env(key) is not None`. |
| Env var source | `env_source(key)` → `"vault" \| "env" \| "default" \| "missing"` | **Dropped.** No more sources to distinguish — only vault. |
| Defaults parameter | `open(defaults={...})` | **Dropped.** Operators wire their own fallback: `v.env(key) or my_default`. |
| Asset bytes | `get_as_content(name)` → bytes | `asset(name)` → **string** (UTF-8 decoded); `assetAsBytes(name)` → bytes. Most assets are text (PEMs, JSON service-accounts). |
| Iteration | not exposed | `keys()` → iterator of env-var names; `files()` → iterator of asset names. |
| Generation | `generation()` → int | unchanged. Cheap local accessor (no network). |
| Has-new-version polling | `has_new_version()` → bool (network HEAD) | **Folded into `status()`.** |
| Status check | not exposed | **`status(test_passphrase=...)` → Status** — rich object with local + remote generation, has-new-version, passphrase-changed, optional safe-to-restart. |
| Close | `close()` / context-manager protocol | **Dropped.** Garbage collection clears the in-memory bundle. Operators that want explicit zeroing can `del v`. |
| Module-level singleton | `vsync_s3_client.get_env(key)` opens lazily | **Dropped.** Operators hold the handle explicitly. |
| Error classes | 7 (see v0.12 §6) | 7, lightly renamed where v0.15 changes scope (see §7) |

Migration impact: every v0.12 consumer needs a 1-line edit (`open()` → `open(cfg, pp)` with the values they fetch). The fallback-chain consumers need to write the `os.environ.get` fallback themselves at the call site. See §10 for the migration table.

## 2. The open path — one factory, no magic

### 2.1 Signature (Python reference)

```python
class VsyncClient:
    @staticmethod
    def open(config_blob: str, passphrase: str) -> "VsyncClient": ...
```

`config_blob` is the magic-prefixed gzip+base64url JSON string emitted by `vsync runtime-token` (the spec calls it the `VSYNC_CONFIG` payload). `passphrase` is the unwrap secret.

Both arguments are required positional. There is no `open_with(...)`, no `open_from_env(...)`, no overloads. Operators that fetch their bootstrap from somewhere other than env vars do the fetching themselves and pass strings:

```python
# Plain env vars
client = VsyncClient.open(
    os.environ["VSYNC_CONFIG"],
    os.environ["VSYNC_PASSPHRASE"],
)

# Files (Docker secrets / Kubernetes mounted secrets)
client = VsyncClient.open(
    Path("/run/secrets/vsync-config").read_text().strip(),
    Path("/run/secrets/vsync-passphrase").read_text().strip(),
)

# Cloud KMS / Vault / Bun.secrets / whatever
cfg = my_secrets_layer.fetch("vsync-config")
pp  = my_secrets_layer.fetch("vsync-passphrase")
client = VsyncClient.open(cfg, pp)
```

The lib's surface area for *getting* the bootstrap is exactly zero. That's the point.

### 2.2 What `open()` does internally

Identical to v0.12's pull path — no protocol changes:

1. Decode `config_blob` (magic check → base64url decode → gunzip → JSON parse → schema-version check).
2. Build the S3 client from the bootstrap's `{endpoint, region, accessKeyId, secretAccessKey}`.
3. Fetch `<prefix>manifest` (RQEM0001 envelope), verify the pointer-seal embedded timestamp matches the object's HEAD-returned `Last-Modified`.
4. Fetch the bundle keyed by `<prefix><gen>.bundle`.
5. Decrypt the RQE1 bundle with `passphrase`.
6. Parse the inner JSON (the decrypted vault), stash `env_map` and `assets_map` in memory.
7. Record `generation`, `bundle_ts`, `opened_at`.
8. Return the handle.

One S3 round trip (HEAD + GET on manifest + GET on bundle = effectively two HTTP requests after the manifest HEAD-then-GET optimization in v0.4 §6). Same as v0.12. The change is purely in the API, not the wire.

### 2.3 Cross-language naming

| Language | Factory call | Notes |
|---|---|---|
| Python | `VsyncClient.open(blob, pp)` | `open` as a static method. Doesn't shadow the builtin because it's class-scoped. |
| TypeScript | `VsyncClient.open(blob, pp)` | Static class method; returns `Promise<VsyncClient>` because the S3 fetch is async. |
| Go | `vsync.Open(blob, pp)` or `vsync.NewClient(blob, pp)` — **pick `Open`** to match the others. Returns `(*Client, error)`. |
| Java | `VsyncClient.open(blob, pp)` | Static method on the class; returns `VsyncClient`; throws checked exceptions for the typed errors. |

One name across all four. No `Create`, no `Initialize`, no `Connect`. The same word the operator types in Python is the same word they type in Go.

## 3. The Status object

`status()` is the single observability accessor. It rolls together everything the operator might want to check: local snapshot info, remote freshness, passphrase rotation, optional safe-to-restart verification.

### 3.1 Schema

```python
@dataclass(frozen=True)
class Status:
    # Local snapshot — populated at open() time, no network needed for these
    local_generation:    int
    local_bundle_ts:     datetime  # the bundle's encoded timestamp from RQEM0001
    opened_at:           datetime  # when VsyncClient.open() returned
    keys_count:          int       # len(env_map) at open
    files_count:         int       # len(assets_map) at open

    # Remote snapshot — populated by status() via a HEAD on the manifest
    remote_generation:   int
    remote_bundle_ts:    datetime
    checked_at:          datetime  # when status() ran

    # Derived flags
    has_new_version:     bool      # remote_generation > local_generation
    passphrase_changed:  bool      # detected via a HEAD attempt that returns a different RQE1 salt
                                   # (best-effort; see §3.3)

    # Optional safe-restart verification (None when test_passphrase not supplied)
    safe_to_restart:     Optional[bool]
```

The frozen dataclass / read-only struct shape carries through to every language:

- TS: `interface Status { readonly … }`
- Go: `type Status struct { … }` — exported fields are stable
- Java: `record Status(…)` (JDK 17+; v0.15 already requires it for the lib)

### 3.2 `status(test_passphrase=...)` semantics

```python
def status(self, test_passphrase: Optional[str] = None) -> Status: ...
```

Always does:

1. HEAD on `<prefix>manifest` → reads the manifest's `Last-Modified` (or the embedded RQEM0001 timestamp via a small GET — implementations choose; spec doesn't pin).
2. GET on `<prefix>manifest` → parses the RQEM0001 envelope, extracts `generation` and the embedded `bundle_ts`.
3. Compares against `local_generation` → sets `has_new_version`.
4. Compares the manifest's stored salt against the open-time salt → sets `passphrase_changed` (heuristic; see §3.3).

When `test_passphrase` is supplied, **also** does:

5. GET on `<prefix><remote_generation>.bundle`.
6. Attempts to decrypt with `test_passphrase`.
7. Sets `safe_to_restart = True` on success, `False` on AES-GCM tag failure.

The trial decrypt only runs when `test_passphrase` is supplied. Without it, `safe_to_restart` is `None` and the operator gets back-of-the-envelope flags only.

Use case for `safe_to_restart`:

```python
# Container running with old VSYNC_PASSPHRASE; teammate rotated the passphrase
# on the bucket; operator pre-updated the platform secret to a new value.
# Before triggering a restart, verify the new passphrase actually decrypts the
# latest bundle:

new_pp = os.environ.get("VSYNC_PASSPHRASE_NEXT")  # operator-set staging slot
if new_pp:
    s = client.status(test_passphrase=new_pp)
    if s.safe_to_restart:
        # The new passphrase works. Restart the process to pick it up.
        trigger_restart()
    else:
        # New passphrase doesn't decrypt the latest bundle yet.
        # Operator hasn't finished the rotation — don't restart blindly.
        logger.warning("VSYNC_PASSPHRASE_NEXT does not unlock the current bundle")
```

The operator's wrapper code drives the workflow; the lib gives them the one boolean.

### 3.3 `passphrase_changed` — heuristic, not authoritative

A bundle written with a different passphrase has a different PBKDF2 salt (the salt is randomized per-write per v0.2 §3.4). On `status()`, the lib peeks at the salt in the manifest's stored RQE1 envelope (without attempting decryption) and compares it to the salt seen at open time. **Different salt → `passphrase_changed = True`.**

Caveat: a teammate who rotated the AES key in their keychain but kept the same passphrase produces a new salt too. So `passphrase_changed` reliably signals "the rotation is non-trivial enough that you should run the safe-to-restart check," not "the human-typeable passphrase value differs." The cheaper "Has a new salt appeared?" check is good enough for the decision gate; `safe_to_restart` is the authoritative answer.

### 3.4 Cost

| Method | Cost |
|---|---|
| `status()` (no `test_passphrase`) | 1 HEAD + 1 GET on manifest (~10KB) |
| `status(test_passphrase=...)` | + 1 GET on bundle (size depends on vault) + 1 decryption attempt |

Operators that poll frequently (every minute) should use `status()` without `test_passphrase`. The full safe-restart check is intended for the *one* call right before triggering a restart, not for ambient polling.

## 4. Method surface — full contracts

### 4.1 `env(key) → str | None`

Vault-only lookup. Returns the value if `key` is in the decrypted env_map; `None` otherwise.

```python
v.env("DATABASE_URL")         # → "postgres://..."
v.env("NOT_IN_VAULT")          # → None
v.env("DATABASE_URL") or "fallback"   # operator-side fallback if they want one
```

No fallback chain. No `os.environ` lookup. No `defaults={}` parameter on `open()`. If the operator wants an env-var fallback, they write it themselves at the call site. The lib has one source of truth: the vault.

### 4.2 `asset(name) → str` and `assetAsBytes(name) → bytes`

Asset lookup. `asset()` decodes the bytes as UTF-8 (raises `UnicodeDecodeError` on invalid UTF-8); `assetAsBytes()` returns raw bytes.

```python
v.asset("gcp-sa.json")            # → '{"type": "service_account", …}'
v.asset("server.crt")             # → '-----BEGIN CERTIFICATE-----\n…'
v.assetAsBytes("keystore.p12")    # → b'\x30\x82…'
```

Returns `None` if the asset is absent. `assetAsBytes` returns `None` on absent; `asset` raises if the asset exists but isn't valid UTF-8.

Rationale for string-by-default: in practice, almost every operational asset (PEM, JSON service account, INI configs, JKS-as-text, vault tokens) is text. Returning bytes by default forced every caller to `.decode("utf-8")` at the boundary. Defaulting to string moves the friction to the (rare) binary case.

### 4.3 `keys()` and `files()`

Iterators over the names of the vault's env-map and asset-map respectively. Order: insertion order from the bundle's encoded JSON (stable across pulls of the same generation).

```python
for k in v.keys():
    print(k, v.env(k))

if "gcp-sa.json" in list(v.files()):
    setup_gcp_credentials(v.asset("gcp-sa.json"))
```

In strongly-typed languages they return `Iterable<String>` / `Iterator<string>`; in Go, `[]string` is acceptable too if iterator semantics feel forced (`Keys() []string`).

### 4.4 `generation() → int`

The integer generation of the bundle this client was opened with. Cheap; no network. Safe to log.

### 4.5 `status(test_passphrase=None) → Status`

See §3. Returns a frozen Status snapshot.

### 4.6 What's NOT in the surface

- No `close()` / `__exit__` / `Closeable` / context manager. Garbage collection clears the bundle bytes; operators that want explicit zeroing can `del v` or set `v = None`.
- No `refresh()` / `reload()` / `pull()`. To get a new bundle, operators construct a new `VsyncClient.open(...)`. Reloading in place would imply hidden state mutation; explicit re-open is cleaner.
- No `has_env(key)`. Replace with `v.env(key) is not None`.
- No `env_source(key)`. Only one source exists.
- No `defaults={}` parameter. Operator writes their own fallback at the call site.
- No `with vsync_s3_client.open() as v: …` recommendation. The lib doesn't need a context manager because there's nothing to release. (Operators can still use one if their language requires it for `try-with-resources`-style flow; it just doesn't gain them anything.)

## 5. Behaviour contracts

### 5.1 Redaction

`repr(v)` / `str(v)` returns `<VsyncClient: redacted gen=N>`. Vault values never leak through stringification. `Status` objects are safe to serialize / log — every field is either a count, a timestamp, or a boolean. Bundle contents are never exposed in any introspection path.

### 5.2 Errors

Same 7-class taxonomy as v0.12, with minor scope changes:

| Class | When |
|---|---|
| `ConfigMissingError` | `open()` got an empty / `None` config or passphrase string. |
| `ConfigUnsupportedVersionError` | Bootstrap blob's inner JSON `v:` newer than this library. |
| `S3UnreachableError` | Network, DNS, TLS, or HTTP 4xx/5xx on any fetch. |
| `ManifestNotFoundError` | Bucket reachable, `<prefix>manifest` absent. Operator hasn't pushed yet. |
| `WrongPassphraseError` | AES-GCM tag rejected the passphrase. |
| `BundleCorruptError` | Magic byte mismatch, truncated read, manifest→bundle dangling, RQEM0001 timestamp seal mismatch. |
| `UnsupportedSpecVersionError` | Unknown RQE1 / RQEM0001 envelope version. |

All inherit from `VSyncError`. Class names cross language boundaries — the conformance corpus matches on the unqualified class name (per [`v0.11`](./v0.11-conformance-test-vectors.md)).

`status(test_passphrase=...)` that hits `WrongPassphraseError` during the trial decrypt **does not raise** — it sets `safe_to_restart = False` and returns the Status normally. The whole point of the trial is to probe non-fatally.

### 5.3 Behaviour under network failure

`open()` always raises on S3 failure. There is no "degrade gracefully to env vars" mode (that's the whole reason fallback-chain was removed). A process that booted via vsync either has the vault, or it crashes and the operator's process manager retries. Loud failure beats silent half-state.

`status()` on network failure returns a Status with `remote_generation = -1`, `has_new_version = False`, `checked_at` populated, `safe_to_restart = None`. Doesn't raise; status is observability and should never crash the caller.

### 5.4 Concurrency

`VsyncClient` instances are read-only after `open()` returns. Multiple threads can share one client and call any combination of `env`, `asset`, `keys`, `files`, `generation`, `status` concurrently. `status()` makes network calls; the lib doesn't serialize concurrent `status()` calls (each fires its own request) — operator is responsible for rate-limiting if needed.

## 7. Error class taxonomy — rename diff

No new classes vs v0.12. Two scope tweaks:

- `ConfigMissingError` now triggers on `open()` receiving empty or `None` strings, not on env-var absence (env vars are no longer in scope). Message updates to reflect the new shape:

  ```
  ✗ VsyncClient.open() requires non-empty config_blob and passphrase.
    config_blob: <empty / None>
    passphrase:  <non-empty>
  ```

- `WrongPassphraseError` is now optionally suppressed inside `status(test_passphrase=...)` — caught internally and converted to `safe_to_restart = False`. Outside that one path, it raises as before.

## 10. Migration from v0.12

Every consumer needs a code edit. There's no shim. The migration table:

| v0.12 call | v0.15 equivalent |
|---|---|
| `vsync_s3_client.open()` | `VsyncClient.open(os.environ["VSYNC_CONFIG"], os.environ["VSYNC_PASSPHRASE"])` |
| `vsync_s3_client.open_with(config=cfg, passphrase=pp)` | `VsyncClient.open(cfg, pp)` |
| `vsync_s3_client.open(defaults={"PORT": "8080"})` | `VsyncClient.open(cfg, pp)` + `v.env("PORT") or "8080"` at call site |
| `v.get_env("X")` | `v.env("X")` |
| `v.has_env("X")` | `v.env("X") is not None` |
| `v.env_source("X")` | (no replacement — only vault exists; operators that need the info know it's vault) |
| `v.get_as_content("a.json")` (bytes) | `v.assetAsBytes("a.json")` |
| `v.get_as_content("a.json").decode()` | `v.asset("a.json")` |
| `vsync_s3_client.get_env("X")` (module-level singleton) | `# Operator holds the client explicitly` |
| `v.has_new_version()` | `v.status().has_new_version` |
| `with vsync_s3_client.open() as v: ...` | `v = VsyncClient.open(cfg, pp); ...` (no `with`) |
| `v.close()` | `del v` (or just let it go out of scope) |

Recommendation: each consumer's first 0.15 PR is a mechanical search-replace of the call sites, followed by removing dead helper code (`_FILE` parsing, etc.) that's now in the lib's old territory.

## 11. Non-goals

- **Env-var helpers.** Not in core; not in a separate module; not as `VsyncClient.open_from_env`. If we ever ship one, it's a separate package.
- **Auto-refresh / background polling.** The lib never opens a thread. Operators that want to re-pull do it explicitly via a new `VsyncClient.open(...)`.
- **`close()` / context manager.** Not adding ceremony for resources that don't exist.
- **In-process secret rotation.** No "swap to the new bundle without restarting" API. Restart is the rotation primitive; `status(test_passphrase=...)` exists to make restarts safe.
- **Caching across opens.** Two consecutive `VsyncClient.open(...)` calls make two independent S3 round trips.
- **Async generation polling.** No `wait_for_new_version()`. Operators that need pub/sub semantics build it on top of `status()`.
- **Sub-keys / nested lookups.** `env(key)` returns a single string; if the operator's vault stores JSON-encoded values, they parse the string themselves.
- **Tempfile materializers.** Dropped from v0.13/v0.14; remains dropped. Operators write tempfiles themselves at the call site (the 3-line recipe in v0.12 README).
- **Bun.secrets / OS keychain integration in the lib.** The lib reads strings; operators wire whatever keychain they want at their layer.

---

## 12. Compatibility & migration

- Wire format (RQE1, RQEM0001, share files, audit log, runtime-token blob): unchanged.
- 0.14.x bundles ↔ 0.15.0 readers: mutually compatible (no protocol change).
- API: hard-breaking. Every v0.12 / v0.14 consumer needs code edits per §10. No shim, no deprecation cycle — pre-1.0 license.
- Package versioning: all four libs bump to `0.15.0` in lockstep. The CLI continues to ship at its own version stream; v0.15 only ships the lib changes. (Unified-version policy across CLI + libs from v0.11 still applies — CLI also bumps to 0.15 in the same release for label consistency.)

## 13. Relationship to other specs

- **v0.2 / v0.4** — wire formats. Unchanged.
- **v0.10** — `vsync runtime-token` produces the `VSYNC_CONFIG` blob that v0.15 `open()` consumes. No CLI changes needed.

v0.15, v0.16, and v0.17 are independent specs that can ship in any order or together. Recommended sequencing: ship v0.16 + v0.17 first (CLI-only changes, faster to land), then v0.15 (touches 4 language ports, conformance corpus, all docs).
